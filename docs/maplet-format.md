# Maplet 문서 형식 v1

`.maplet`은 Maplet의 기본 문서 형식인 UTF-8 JSON이다. `.mup`은 MindMup과 데이터를 교환하는 호환 형식이다. 설계 결정은 [ADR 0009](adr/0009-native-maplet-format.md)를 참고한다.

## 최소 예제

```json
{
  "format": "maplet",
  "version": 1,
  "roots": ["root"],
  "nodes": {
    "root": {
      "id": "root",
      "title": "중심 주제",
      "parentId": null,
      "children": [],
      "rank": "1",
      "side": "right",
      "collapsed": false,
      "position": null,
      "style": {},
      "notes": "",
      "links": []
    }
  }
}
```

실제로 열어 볼 수 있는 [좌표와 확장이 포함된 예제](../tests/fixtures/native-v1.maplet)도 제공한다.

## 문서와 노드

| 필드            | 의미                                      |
| --------------- | ----------------------------------------- |
| `format`        | 문자열 `maplet`                           |
| `version`       | 현재 정수 `1`. 지원하지 않는 버전은 거절  |
| `roots`         | 루트 ID 목록. 비어 있을 수 없고 중복 불가 |
| `nodes`         | 노드 ID를 키로 사용하는 노드 객체 목록    |
| `compatibility` | 선택적 호환 메타데이터                    |

노드의 아래 필드는 모두 필수다. 노드 ID 키와 `id`는 같아야 한다.

| 필드        | 의미                                                                        |
| ----------- | --------------------------------------------------------------------------- |
| `id`        | 비어 있지 않은 문자열. 위험 ID `__proto__`·`constructor`·`prototype` 거절   |
| `title`     | 제목 문자열. 최대 10,000자                                                  |
| `parentId`  | 부모 ID. 루트는 `null`                                                      |
| `children`  | 자식 ID의 순서 있는 목록                                                    |
| `rank`      | 0이 아닌 유한한 숫자로 해석되는 순서 문자열. 같은 부모의 자식끼리 중복 불가 |
| `side`      | 자동 배치 방향인 `left` 또는 `right`                                        |
| `collapsed` | 접힘 여부인 boolean                                                         |
| `position`  | 자동 배치이면 `null`, 수동 배치이면 `{ "x": 100, "y": 200 }`                |
| `style`     | 배경색 등을 담는 JSON 객체                                                  |
| `notes`     | 일반 텍스트 메모 문자열                                                     |
| `links`     | 링크 문자열 목록. 실제 링크 열기와 수정은 별도 안전 URL 정책 적용           |

`position`은 확대·팬과 독립적인 맵 좌표에서 노드 왼쪽 위를 뜻한다. 좌우 배치 정보와 좌표는 별도다. 수동 좌표가 있으면 좌표를 우선해 표시한다. 부모를 이동하면 자손 좌표도 함께 평행 이동한다. 캔버스 확대율·팬·현재 선택·Undo 히스토리는 v1 문서에 저장하지 않는다.

참조하는 모든 노드는 존재해야 하고 부모와 자식 정보가 일치해야 한다. 각 노드는 루트에서 정확히 한 번 도달할 수 있어야 한다. 고립 노드·중복 참조·순환 계층은 거절한다. 여러 루트를 허용하고 루트 rank도 중복할 수 없다.

## 확장과 버전

인식하지 않는 최상위 필드와 노드 필드는 읽기·편집·저장 시 보존한다. 확장에는 충돌을 피할 수 있는 이름을 사용한다. `style`과 호환 메타데이터 안의 알 수 없는 속성도 유지한다. `position`은 v1의 x/y 좌표로 해석한다.

알 수 없는 `version`을 추정해 열거나 MUP으로 재해석하지 않는다. 새로운 버전을 지원할 때는 명시적 변환과 이전 버전 fixture 회귀 테스트를 추가한다. 현재 다른 네이티브 버전에서 v1로 강제 변환하는 기능은 없다.

## MindMup 호환 데이터

MindMup에서 가져온 문서는 선택적으로 다음 영역을 포함한다.

```text
compatibility.mindmup
  formatVersion   원래 MUP 버전 1 / 2 / 3
  original        가져온 원본 텍스트 또는 null
  document        문서 수준의 원본 확장 속성
  warnings        표시 제한 안내
  nodes[id]
    originalId    원래 ID와 타입
    raw           해당 노드의 원본 확장 속성
```

이 영역은 원본 보존과 MUP 내보내기에 사용한다. 현재 편집 내용은 항상 기본 `nodes`에 있고 호환 메타데이터가 편집 내용을 덮어쓰지 않는다. 새 네이티브 문서에는 MUP 데이터가 필요 없다. MUP으로 내보낼 때 알려진 편집 필드만 원본 데이터에 반영한다. 수동 좌표는 기존 Maplet 확장 `attr["maplet:position"]`으로 내보내지만 타 편집기가 같은 배치를 보장하지는 않는다.

Maplet 고유 확장은 MUP으로 모두 표현되지 않을 수 있다. `.mup 내보내기`는 기본 문서 저장을 대신하지 않으며 `.maplet 저장`으로 작업 원본을 보관한다. 원본 백업 메뉴는 가져온 MindMup 텍스트를 그대로 다운로드한다.

## 한도와 초안 이전

- `.maplet`: 최대 50 MiB. MUP 원본과 확장 속성을 함께 담는 공간을 포함한다.
- `.mup`: 최대 10 MiB.
- 공통: 노드 5,000개, 깊이 100단계, 제목 10,000자, 좌표의 각 축은 유한한 ±1,000,000.
- JSON의 비유한 숫자, 잘못된 속성 타입과 계층은 거절한다. 파일 오류는 현재 편집 문서를 교체하지 않는다.

IndexedDB의 기존 MUP 초안은 복구할 때 네이티브 내용으로 이전한다. 현재 내용과 저장 기준 내용을 함께 정규화하고 MUP 원본 텍스트를 보존한다. 저장소를 초기화하지 않으므로 업그레이드 이전의 편집 내용을 복구할 수 있다.

Drive에서 연 `.mup` 파일을 저장하면 새 `.maplet` 파일을 만든다. 네이티브 파일 갱신에는 기존 버전·ETag 충돌 검사를 적용한다.
