# ADR 0007: 코드 파일당 400줄 제한

- 상태: 채택
- 날짜: 2026-10-17

## 배경

App·Canvas·Editor와 공통 CSS가 커지면서 문서 조작, 외부 연동, 노드 표시, 메뉴, 스타일 책임이 한 파일에 모였다. 사용자는 파일이 계속 커지는 것을 린트에서 차단하기 위해 약 400줄 제한을 요청했다.

## 결정

ESLint `max-lines`를 오류 수준으로 설정한다. TypeScript·TSX·JavaScript·MJS 운영 코드, 테스트, 스크립트, 설정 파일에 동일하게 적용한다. 빈 줄과 주석도 포함하며 파일 끝 개행은 추가 줄로 세지 않는다. 400줄은 허용하고 401줄부터 실패한다. 파일별 예외나 기존 초과 파일의 유예는 두지 않는다.

ESLint가 해석하지 않는 `src/**/*.css`에는 `scripts/check-style-lines.mjs`로 같은 줄 수 기준을 적용하고 `npm run lint`에 연결한다. 문서·포맷 fixture·이미지·빌드 및 테스트 산출물은 이 제한의 대상이 아니다.

파일을 나눌 때 책임을 기준으로 경계를 정한다. 줄을 압축하거나 순환 참조로 파일 간 책임을 묶어 제한을 피하지 않는다. 기존 계층 의존·순환 참조 테스트와 Prettier를 함께 유지한다.

App에서 Drive 수명주기는 `useDrive`, 연결·충돌 UI는 `DriveDialogs`로 분리한다. 단축키 안내는 별도 컴포넌트로 둔다. Canvas는 뷰포트와 제스처를 담당하고 `CanvasNodes`가 노드 표시와 인라인 편집을 담당한다. 공통 타입은 독립 모듈에 두어 역참조를 피한다. 툴바 메뉴는 자체 닫기 동작을 가진 컴포넌트로 분리한다. CSS는 기본 요소·에디터·캔버스·대화상자·반응형 규칙으로 나눈다.

## 검증

실제 ESLint 설정으로 운영·테스트·스크립트 경로에서 400줄 허용과 401줄 거절을 검증한다. 빈 줄과 주석도 제한에 포함되는지 검사한다. 규칙 추가 전 테스트 실패와 추가 후 기존 3개 파일의 린트 실패를 확인한 뒤 리팩터링한다. CSS는 하위 폴더와 CRLF 개행의 경계 조건을 테스트한다. 분리 후 아키텍처 검사, 전체 품질 검사, 브라우저 회귀 테스트를 실행한다.
