# ADR 0018: 사용자 동작으로 Drive 인증 연장

- 상태: 채택, 실제 OAuth 환경 검증 대기
- 날짜: 2026-10-24
- 관련: [ADR 0003](0003-drafts-and-drive.md)의 메모리 인증, [ADR 0016](0016-tab-auth-sharing.md)

## 배경

Google token model의 액세스 토큰은 약 1시간 유효하고 refresh token이 없다. 지금까지는 만료 후 다음 자동 저장이 실패해야 연결 끊김이 드러났다. 사용자는 편집 중에 갑자기 `자동 저장 중지`를 보게 되었다. 서버 없이 토큰을 새로 받으려면 `requestAccessToken`을 다시 호출해야 한다. 이 호출은 팝업을 열기 때문에 사용자 동작 안에서만 실행된다. 타이머로 호출하면 브라우저가 팝업을 차단한다.

## 결정

- `GoogleConnection`은 토큰을 받을 때 만료 10분 전에 `expiring`, 만료 시점에 `expired` 이벤트를 발생시킨다. 다른 탭에서 받은 토큰과 새로 받은 토큰도 같은 일정으로 다시 예약한다. 만료 시점에는 메모리 토큰만 지우고 진행 중인 OAuth 응답은 무효화하지 않는다. 연장 팝업이 열린 채로 만료돼도 그 응답을 받는다.
- 연장 구간에서 사용자가 앱을 클릭하면 `requestAccessToken({ prompt: '' })`로 토큰을 다시 받는다. 이미 동의한 계정은 팝업이 바로 닫힌다. 키 입력은 팝업이 포커스를 가져가 타이핑이 끊기므로 사용하지 않는다. Drive 작업이 진행 중이면 기다린다.
- 헤더 Drive 상태에 `곧 만료`와 `연장` 버튼을 표시한다. 오류가 아니라 경고 색으로 표시한다. 키보드만 쓰는 사용자도 버튼으로 연장할 수 있다.
- 자동 연장이 실패하면(팝업을 닫거나 차단) 그 토큰이 끝날 때까지 클릭 연장을 다시 시도하지 않는다. 클릭할 때마다 팝업이 다시 열리지 않게 하기 위해서다. 헤더 버튼은 계속 동작하며 실패를 알린다.
- 연장된 토큰은 기존 `BroadcastChannel`로 다른 탭에 전달되어 모든 탭의 경고가 사라진다.
- 만료되면 헤더가 즉시 `다시 연결 필요`로 바뀌고 자동 저장을 시작하지 않는다. 편집은 기기 초안에 남고, `다시 연결` 후 이어서 저장한다.

## 한계

- Google 세션이 끝났거나 여러 계정에 로그인되어 있으면 연장 팝업에서 계정을 선택하거나 로그인해야 한다.
- 연장 구간 동안 클릭이나 버튼 조작이 없으면 기존처럼 만료되며 재연결이 필요하다.
- 실제 팝업의 자동 닫힘과 차단 동작은 모킹 테스트로 확인할 수 없어 실제 계정으로 검증해야 한다.

## 검증

단위 테스트는 연장 구간·만료 이벤트 시각, 재인증 후 일정 재예약, 만료 중 열린 연장 응답 수락, 연결 해제 후 일정 중지를 검사한다. Hook 통합 테스트는 클릭 연장, 키 입력 무시, 실패 후 클릭 연장 중지와 버튼 연장, Drive 작업 중·만료 후 연장 차단, 다른 탭의 연장 반영을 검사한다. 브라우저 테스트는 클릭과 헤더 버튼으로 연장한 뒤 원래 만료 시각 이후에도 자동 저장되는지, 만료 후 `다시 연결 필요`를 표시하고 재연결 후 저장하는지 확인한다.
