# ADR 0016: 열린 탭 간 메모리 인증 공유

- 상태: 채택, 실제 OAuth 환경 검증 대기
- 날짜: 2026-10-21
- 관련: [ADR 0003](0003-drafts-and-drive.md)의 "GitHub Pages 유지 및 메모리 인증 복귀"

## 배경

새 맵을 새 브라우저 탭으로 여는 방향을 검토했다. 액세스 토큰을 메모리에만 두기 때문에 탭마다 `다시 연결`을 눌러야 한다. 쿠키를 검토했지만 정적 배포에서는 JS가 만든 쿠키에 `HttpOnly`를 붙일 수 없다. 이 쿠키는 localStorage와 똑같이 XSS에 노출되고, 같은 origin으로 가는 모든 요청에 실려 GitHub Pages로 전송된다. 그래서 채택하지 않았다. 서버 세션(BFF)은 정적 배포 유지 결정과 충돌한다.

## 결정

같은 origin에서 열린 탭끼리 `BroadcastChannel`(`maplet:auth:{clientId}`)로 메모리 토큰을 전달한다. 토큰은 sessionStorage, localStorage, IndexedDB, 쿠키 어디에도 쓰지 않는다. 모든 탭을 닫으면 토큰도 사라진다.

- 탭이 시작하면 `request`를 보내고, 유효한 토큰이 있는 탭이 `token`으로 응답한다. 인증에 성공한 탭도 같은 메시지로 다른 탭에 알린다.
- `token`은 절대 시각이 아니라 남은 수명(`expiresIn`)을 전달한다. 받는 탭은 자기 시계로 만료 시각을 계산하며 Google이 정한 만료를 늘리지 않는다. 지금 가진 토큰보다 늦게 만료되는 토큰만 받는다.
- 401로 인증을 지운 탭은 `expired`에 해당 토큰을 담아 보낸다. 같은 토큰을 가진 탭만 연결 끊김으로 전환하고, 더 새로운 토큰은 유지한다.
- 연결 해제는 `disconnected`를 보낸다. 다른 탭도 인증·저장 위치·문서 대상을 모두 초기화하고 진행 중인 OAuth 응답을 무효화한다. 권한 철회는 해제를 누른 탭에서 한 번만 실행한다.
- 메시지는 형식을 검증한 뒤 처리한다. `BroadcastChannel`이 없거나 생성에 실패하면 기존처럼 탭마다 직접 재연결한다.
- 토큰을 받은 탭은 기억한 작업 위치를 기존 자동 복원 경로로 복원한다. 미저장 초안의 복구 선택을 먼저 기다리고, OAuth 창이나 Picker는 열지 않는다. 다른 탭이 없을 때 새로고침하면 지금처럼 재연결이 필요하다.

## 한계

- 같은 origin의 다른 페이지도 채널에 참여해 토큰을 요청할 수 있다. 예를 들어 `username.github.io`의 다른 프로젝트 페이지가 그렇다. 이런 페이지는 이미 같은 origin의 초안 저장소에 접근할 수 있지만, 이 결정으로 토큰 획득이 쉬워진다. 배포는 Maplet 전용 origin(사용자 지정 도메인 등)을 권장한다.
- 모든 탭을 닫은 뒤에는 사용자 클릭으로 다시 인증해야 한다. Google token model은 refresh token을 발급하지 않는다. 열린 탭의 만료 전 연장은 [ADR 0018](0018-gesture-auth-renewal.md)에서 다룬다.
- Drive 작업 위치(localStorage)와 초안(IndexedDB `current`)은 아직 기기당 한 개다. 새 탭이 다른 탭의 최근 파일을 복원해 두 탭이 같은 파일을 저장할 수 있다. 버전 검사가 충돌로 막지만, 탭별 작업 위치·초안 분리는 새 탭 새 맵 결정에서 다룬다.

## 검증

단위 테스트는 탭 간 전달, 남은 수명 유지, 오래된 만료 알림 무시, 전체 해제와 1회 철회, 해제 후 늦은 OAuth 응답 차단, 메시지 검증, 채널이 없을 때의 대체 동작을 검사한다. 브라우저 테스트는 새 탭이 인증 창 없이 연결되고 저장소에 토큰이 없으며, 한 탭의 해제가 다른 탭의 자동 저장을 멈추는지 확인한다.
