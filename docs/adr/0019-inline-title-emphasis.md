# ADR 0019: 제목 안 글자 단위 강조

- 상태: 채택
- 날짜: 2026-11-05
- 관련: [ADR 0004](0004-minimal-editor-interface.md)의 인라인 편집, [ADR 0009](0009-native-maplet-format.md)

## 배경

노드 서식의 굵게·기울임은 제목 전체에만 적용된다. 사용자는 제목 안의 특정 글자만 굵게 하거나 형광펜처럼 배경색을 넣어 가독성을 높이고 싶어 했다. 대화상자 없이 단축키로 바로 적용되고, 형광펜 색은 여러 개 중에서 직접 고르기를 원했다.

첫 구현은 textarea를 유지하고 편집 중에 `**`·`==` 기호를 그대로 보여 주었다. 형광펜 단축키는 누를 때마다 색을 순환했다. 사용자 검토에서 편집 중 기호 때문에 읽기 어렵고 색을 순환으로 고르기 불편하다는 피드백을 받아, 편집 중에도 결과만 보이고 우클릭 메뉴로 색을 고르는 방식으로 바꿨다.

## 결정

- 저장은 제목 문자열 안의 마크다운식 기호로 한다. 굵게는 `**글자**`, 형광펜은 `==글자==`(노랑) 또는 `=={green}글자==`다. 색은 노랑·초록·파랑·분홍 네 가지다. 문서 형식 v1, 앱 실행 취소, Drive 병합, 클립보드, 내보내기는 바뀌지 않고 모두 `title` 문자열을 그대로 다룬다. 범위 배열(`style.marks`)은 Drive 병합에서 제목과 따로 충돌할 수 있어 쓰지 않는다.
- 인라인 편집기는 `contenteditable="plaintext-only"` 요소다. 열 때 제목을 서식 조각으로 그리고, 바뀔 때마다 DOM을 다시 기호 문자열로 읽어 미리보기에 넘긴다. 사용자는 기호를 보지 않는다. Maplet이 만든 `strong`·`mark` 요소만 서식으로 인정하고, 붙여넣기는 일반 텍스트로만 받으며, 끌어 놓기와 브라우저 서식 명령은 막는다.
- 입력은 브라우저가 직접 처리해 한글 조합을 유지한다. 조합 중에는 DOM을 다시 그리지 않고, 조합 중에 누른 서식 단축키는 조합이 끝난 뒤 적용한다. Shift+Enter 줄바꿈은 `\n` 글자로 넣고, 비어 있는 마지막 줄은 자리표시 `<br>`로 보이게 한다.
- 서식 명령은 DOM을 다시 그리므로 브라우저 실행 취소가 따라오지 못한다. 그래서 편집 중 실행 취소는 편집기 안의 기록으로 처리한다. 같은 종류의 빠른 입력은 1초 단위로 묶고, 서식 명령은 한 단계씩 기록한다. 편집을 확정하면 앱 기록에는 지금처럼 한 단계로 남는다.
- 편집 중에 글자를 선택하고 우클릭하면 `글자 서식` 메뉴(굵게·형광펜 네 색·서식 지우기)를 연다. 선택이 없으면 브라우저 기본 메뉴를 그대로 둔다. 메뉴를 마우스로 누르면 편집기 포커스와 선택이 유지된다. Shift+F10으로 열면 포커스가 메뉴로 옮겨지고, 닫으면 편집기와 선택이 복원된다.
- 편집 중에는 노드 여백과 캔버스가 선택 가능한 글자가 아니라서, 브라우저는 그쪽으로 끌린 선택을 잃고 여백을 누르면 노드에 포커스를 주어 편집을 끝낸다. 그래서 편집 중 노드 여백에서 시작하거나 글자 밖으로 나간 드래그는 가장 가까운 글자 위치로 선택한다. 위는 처음, 아래는 끝, 옆은 그 줄의 끝이다. 이미 선택된 글자를 누르고 끌면 글자 끌어 놓기 대신 새 선택을 시작한다. 단, 연속 클릭(더블·트리플 클릭)은 브라우저의 단어·전체 선택에 맡긴다. 편집 중인 노드는 클릭·더블클릭을 노드 선택이나 편집 시작으로 처리하지 않는다.
- 단축키: `⌘/Ctrl+B`는 굵게를 토글한다. `⌘/Ctrl+Shift+H`는 메뉴에서 마지막으로 고른 색(처음에는 노랑)을 적용하고, 이미 그 색이면 해제한다. `⌘/Ctrl+\`는 서식을 지운다. 선택이 없으면 커서가 있는 단어에 적용한다. 한글 자판에서는 물리 키로 판단한다.
- 편집 중 노드도 서식이 적용된 상태로 측정한다. 화면 표시와 편집기가 같은 줄바꿈·크기를 가진다. 줄바꿈은 서식 조각 단위로 측정하고 굵은 조각은 굵은 글꼴 폭을 쓴다. 형광펜 배경은 여백 없이 그려 측정 폭과 같다. SVG 내보내기는 측정한 조각 폭으로 글자 뒤에 사각형을 그린다.

## 결과

- 짝이 없는 기호와 감싼 글자가 없는 기호는 글자 그대로 보인다. 이전 문서에 `**`가 짝을 이뤄 들어 있었다면 이제 굵게 보인다. 다른 편집기와 텍스트 내보내기에서는 기호가 보인다.
- 선택이 있는 상태의 우클릭은 브라우저 메뉴 대신 서식 메뉴를 연다. 복사·잘라내기는 키보드 단축키를 쓴다.
- 글자 단위 굵게는 700이다. 기본 굵기가 600인 루트와 노드 전체 굵게(700)가 적용된 노드에서는 구분되도록 800을 쓴다. 시스템 글꼴에 800 굵기가 없으면 차이가 작을 수 있다.
- 실제 macOS 한글 입력기와 서식 단축키의 조합은 CDP 조합 이벤트로만 자동 검사하므로 실제 입력기로도 확인한다.

## 후속 결정: 서식 하나로 정리

검토에서 굵게가 서식 창(노드 전체)과 글자 단위로 나뉘어 있고, 형광펜 색은 우클릭 메뉴에서만 고를 수 있다는 지적을 받았다. 전체 굵게가 켜진 노드에서는 일부 글자만 굵게를 풀 수도 없었다. 그래서 다음과 같이 정리한다.

- 굵게·기울임·형광펜은 모두 제목 안 표기 하나로 저장한다. 기울임은 `*글자*`다. 서식 창에서는 굵게·기울임을 뺀다.
- 상단 툴바에 굵게·기울임·형광펜(현재 색 적용 버튼과 색 선택)을 둔다. 같은 버튼과 단축키(`⌘/Ctrl+B`·`I`·`Shift+H`·`\`)는 편집 중이면 선택한 글자에, 아니면 선택한 노드들의 제목 전체에 적용한다. 노드 여러 개에는 한 번의 실행 취소로 적용한다. 모두 이미 굵으면 풀고, 아니면 모두 굵게 한다. 툴바 버튼은 눌러도 편집기의 포커스와 선택을 가져가지 않는다.
- 형광펜 색은 노드나 문서마다 따로 두지 않는 공통 "현재 색" 하나다. 툴바·우클릭 메뉴에서 고르면 바뀌고, 단축키와 툴바 버튼이 그 색을 쓴다. 브라우저에 기억해 새로고침 후에도 유지한다.
- 이전 문서의 노드 전체 굵게·기울임은 표시를 유지하고, 그 노드의 서식을 바꾸거나 제목을 편집해 바꿀 때 제목 안 표기로 옮긴다. 열기만으로는 문서가 바뀌지 않아 Drive에 불필요한 저장이 생기지 않는다.
- 굵게와 기울임은 겹치는 표시 대신 바뀌는 지점마다 `**`, `*` 순으로 쓴다. 파서는 종류별로 짝을 맞추므로 `***`는 항상 굵게와 기울임 둘로 읽힌다. 중첩으로 쓰면 `****`가 생겨 잘못 읽히는 경우가 있었다.
- 1101~1360px 너비에서는 메모·링크·서식·찾기·자동 배치를 아이콘과 툴팁으로 줄여 툴바가 잘리지 않게 한다.

## 검증

파서와 기호 쓰기의 무작위 왕복 검사(굵게·기울임·형광펜 조합, 직렬화 결함을 되살렸을 때 실패하는지 확인), 노드 단위 서식과 이전 문서의 전체 강조 이전, 툴바와 편집기 연결, 공통 형광펜 색 저장, 범위 서식·삽입, DOM↔조각 변환과 선택 위치 왕복, 편집 기록 묶음, 메뉴와 단축키, 조합 대기를 단위·통합 테스트로 검사한다. Chromium E2E에서 단축키 적용과 편집 중 실행 취소, 우클릭 메뉴의 마우스·키보드 조작, 노드 여백·캔버스로 이어지는 드래그 선택과 연속 클릭, 일반 텍스트 붙여넣기와 줄바꿈, 렌더링 색·굵기, 편집 전·중·후 노드 위치 일치, 기존 한글 조합·인라인 레이아웃 회귀를 확인한다.
