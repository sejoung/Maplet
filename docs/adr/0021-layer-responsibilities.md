# ADR 0021: 계층별 책임 재정리

- 상태: 채택
- 날짜: 2026-11-06
- 관련: [ADR 0001](0001-layered-local-first.md), [ADR 0010](0010-drive-save-queue-and-merge.md), [ADR 0020](0020-architecture-rules-as-tests.md)

## 배경

전체 코드 리뷰에서 의존 방향은 지켜지지만 계층 안쪽의 책임이 기울어 있다는 점이 드러났다. Drive 동기화 규칙이 `app` 훅에 있었고 `application`은 210줄뿐이었다. `domain`에는 화면 픽셀 수치가, `components`에는 좌표 계산과 브라우저 저장소 접근이 섞여 있었다. 불변성은 전체 복제와 구조 공유가 섞여 실행 취소 기록이 데이터를 공유하지 못했다. 포맷·도구·제스처 하나를 추가하려면 7곳 안팎을 고쳐야 했다.

## 결정

- **domain**: 모델·명령·불변식만 둔다. 트리 순회는 `tree.ts`, 불변식은 `invariants.ts`에 한 번씩 둔다. 명령은 `editNodes`(copy-on-write)로 바뀐 노드만 새로 만들고, 아무것도 바뀌지 않으면 같은 참조를 돌려준다. 어떤 함수도 입력을 바꾸지 않는다(입력을 얼린 테스트로 강제). 두 계층이 함께 쓰는 형태(동기화 스냅샷, 환경설정, 외부 저장소)는 domain에 둔다.
- **application**: 동기화 유스케이스 규칙을 순수 함수로 둔다. 저장 판정, 3자 병합과 재병합, 저장 재시도와 미확인 쓰기 처리, 복원 충돌 판정이 여기 있다. 코덱과 Drive 쓰기는 주입받고 상태는 종류(`kind`)로만 표현하며, 화면 문구는 components가 고른다.
- **engine**: 배치·기하·뷰포트(`geometry.ts`, `viewport.ts`)와 화면 수치(`render-metrics.ts`)를 둔다.
- **adapters**: 파일 포맷은 레지스트리(`formats.ts`) 한 곳에 둔다. 포맷이 공통으로 따르는 한도는 같은 메시지 키로 검사한다. Drive·인증·초안 저장소는 인터페이스(`DriveFiles`, `DriveAuth`, `DraftRepository`)로 노출하고, 브라우저 저장소 접근은 `web-storage.ts`로 감싼다. 페이지 언어·테마 반영도 어댑터가 맡는다.
- **i18n**: 카탈로그·번역·언어 상태만 둔다. 브라우저 접근은 조립 지점(`main.tsx`)에서 연결한다.
- **components**: 화면만 그린다. 메뉴·툴바·파일 메뉴·단축키는 데이터(`MenuAction`, `shortcuts.ts`)에서 그린다. 포인터 제스처는 하나의 상태 값으로 관리한다. 노드는 메모이제이션된 컴포넌트로 그려 바뀐 노드만 다시 렌더링한다.
- **app**: 조립과 수명 주기만 맡는다. Drive는 연결·복원·Picker·저장·작업 직렬화 훅으로 나누고, 작업 공간 상태는 리듀서로 다룬다. 어댑터 객체는 조립 지점에서만 만든다.

## 결과

포맷·메뉴 동작·단축키·제스처는 각각 한 곳에 항목을 추가하면 된다. 동기화 규칙은 React 없이 단위 테스트한다. 파일 수와 줄 수는 늘었지만(131 → 185개, 약 13,300 → 15,300줄) 가장 큰 파일은 400줄 한도 안의 동작 목록(`node-actions.ts`, 372줄)이다. 이 결정의 경계 중 기계적으로 확인할 수 있는 부분은 ADR 0020의 아키텍처 테스트가 강제한다.
