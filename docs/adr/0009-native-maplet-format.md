# ADR 0009: Maplet 전용 문서와 MindMup 호환 형식 분리

- 상태: 채택
- 날짜: 2026-10-18
- 대체 범위: ADR 0002·0003·0005의 `.mup` 기반 기본 저장 및 초안 직렬화

## 배경

MindMup은 가져오기·내보내기용 호환 형식이다. Maplet의 좌표와 향후 기능을 계속 외부 포맷 확장에만 저장하면 문서 모델과 제품 확장이 외부 포맷에 묶인다. 사용자는 Maplet의 독립적인 파일 형식을 요청했다.

## 결정

기본 파일 확장자는 `.maplet`, 내용은 공개된 JSON 문서로 정한다. `format: "maplet"`, `version: 1`로 식별하고 루트 목록과 ID별 노드 목록을 직접 저장한다. 노드의 제목·부모·자식·순서·좌우 방향·좌표·접기·메모·링크·스타일이 일급 필드다. MindMup `ideas` 트리를 감싼 래퍼 형식을 사용하지 않는다. [v1 형식 문서](../maplet-format.md)에 구조와 검증 정책을 기록한다.

가져온 MindMup의 버전·원래 ID 타입·알 수 없는 속성·원본 텍스트는 선택적인 `compatibility.mindmup` 영역에 보존한다. 새 Maplet 문서에는 이 영역이 필요하지 않다. 현재 메모리 모델의 기존 호환 필드를 어댑터가 이 영역으로 변환하므로 도메인 편집 명령과 히스토리는 유지한다. 인식하지 못한 네이티브 문서·노드 확장도 보존한다.

기본 저장과 Ctrl/Cmd+S는 `.maplet`을 다운로드한다. `.mup 내보내기`는 파일 메뉴에서 별도로 제공하며 네이티브 저장 완료 상태를 변경하지 않는다. 가져온 MindMup 원본 백업도 유지한다. 열기는 확장자만 신뢰하지 않고 JSON 내용으로 형식을 판별한다. 알 수 없는 네이티브 버전은 기존 문서를 바꾸지 않고 거절한다. 향후 버전은 명시적 마이그레이션을 추가한다.

초안 내용과 저장 기준 내용도 네이티브 형식으로 직렬화한다. 기존 IndexedDB 저장소를 지우거나 버전을 바꾸지 않는다. 복구 시 기존 MUP 초안과 기준 내용을 변환하고 동일한 원본 텍스트를 적용해 원본 공백 차이가 수정 상태로 오인되지 않도록 한다.

Drive는 `.maplet` 내용을 저장한다. `.maplet` 파일은 기존 충돌 검사를 거쳐 갱신하고, Drive에서 연 `.mup` 파일은 새 `.maplet` 파일로 저장해 원본을 덮어쓰지 않는다. 로컬과 Drive 저장 상태는 계속 분리한다.

네이티브 파일은 MUP 원본·호환 메타데이터를 함께 보관할 수 있으므로 가져오기 크기를 50 MiB로 정한다. MUP 한도는 기존 10 MiB를 유지한다. 노드 5,000개·깊이 100단계·제목 10,000자·유한한 ±1,000,000 좌표 제한은 두 형식에 공통 적용한다.

## 검증

네이티브 codec 부재, `.maplet.mup` 다운로드 이름 오류, 기존 초안 마이그레이션 부재를 실패 테스트로 확인한 뒤 구현했다. 재저장 시 JSON 키 순서가 달라지는 실패와 기존 초안 원본 공백 때문에 수정 상태가 생기는 실패도 확인해 수정했다.

독립적으로 작성한 네이티브 fixture, 좌표·계층·스타일 왕복, 5개 MUP fixture의 네이티브 경유 원본 보존, 알 수 없는 필드, 버전·ID·계층·순환·크기·깊이 검증을 테스트한다. E2E는 네이티브 저장/재열기, 별도 MUP 내보내기와 수정 상태 유지, 미래 버전 거절, 이전 MUP 초안 복구를 검사한다.
