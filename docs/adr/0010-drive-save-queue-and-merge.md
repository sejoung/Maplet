# ADR 0010: Drive 저장 큐와 노드·속성 병합

- 상태: 채택, 실제 OAuth 환경 검증 대기
- 날짜: 2026-10-20

## 문제

빈번한 편집과 느린 네트워크에서도 편집을 막지 않고 최신 내용을 저장해야 한다. 파일 버전 변경을 모두 충돌로 안내하면 내용이 같은 변경이나 다른 노드·속성 편집도 사용자가 매번 해결해야 한다. 응답 유실 후 자신의 저장을 외부 편집으로 오인할 수도 있다.

## 결정

자동·수동 저장을 하나의 큐로 통합한다. 실행 중인 내용은 고정하며 대기는 최신 내용 하나로 합친다. 추가 편집은 성공 응답의 버전을 기준으로 이어서 저장한다. 1.5초 debounce와 5초 최대 대기를 사용하며, 문서 키와 세대가 달라지면 후속 요청과 오래된 완료 반영을 취소한다.

파일 버전 불일치·412는 원격 다시 읽기의 신호다. 마지막 Drive 기준 / 로컬 / 원격을 노드 ID와 속성별로 비교한다. 동일 변경과 독립 변경은 병합하고 실제 상충만 선택을 요청한다. 스타일은 키 단위, 좌표와 배열은 값 단위다. 서로 겹치는 하위 가지 이동은 관련 위치를 한 그룹으로 선택하여 드래그가 부분적으로 적용되지 않게 한다. 중복 child 목록은 parent/rank로 재구성하며 충돌하는 구조 영역과 전역 제한을 검증한다. 구조 선택은 관련 없는 추가·수정을 지우지 않는다. 선택 후 저장도 조건부 쓰기로 다시 검증한다.

병합한 원격 변경은 저장 응답을 기다리는 동안에도 로컬 문서·초안·undo/redo 이력에 반영한다. 현재 문서에서 그 사이 발생한 새 편집은 보존한다. 마지막 기준과 기존 파일의 미확인 저장 시도는 IndexedDB 초안에 함께 보관하며 다운로드 완료 상태와 분리한다. 기준이 없는 과거 초안은 기존의 보수적인 충돌 정책을 유지한다.

일시 오류는 원격 내용을 확인하고 횟수를 제한해 재시도한다. 자신의 미확인 저장 내용과 원격이 일치하면 해당 버전을 채택한다. 네트워크 실패를 편집 충돌로 바꾸지 않으며 인증 오류는 자동 로그인하지 않는다. 요청 대기는 30초로 제한한다.

새 파일 생성에는 사전 발급한 Drive 파일 ID를 사용한다. 같은 생성 작업의 재시도는 같은 ID를 사용하고, 409·응답 유실 시 그 ID를 읽어 결과를 확인한다. 현재 세션에서 새 편집으로 재시도해도 자신이 만든 내용임을 확인한 뒤 갱신한다.

## 한계와 후속 작업

- 실제 공유 파일을 여러 클라이언트에서 동시에 쓰는 것을 원자적으로 조정하는 서버는 없다. ETag가 노출되지 않으면 버전 조회와 쓰기 사이 경쟁 구간이 남는다.
- 저장 중 외부 변경을 병합하는 기능이며 다른 사용자의 실시간 편집·접속 상태를 전송하지 않는다. 기존 폴더 밖 파일의 사본 정책을 유지한다.
- 생성 예약 ID는 현재 메모리 세션에서만 유지한다. 새 파일 생성 결과가 불명인 채 페이지를 강제 종료한 경우에는 Drive에서 생성 여부를 확인해야 한다.
- 실시간 공동 편집은 별도 결정에서 통신·권한 검증·변경 로그·단일 Drive 쓰기 담당자를 설계한다.

## 후속 결정: 로컬 버퍼와 네트워크 저장 주기 통합 (2026-10-20)

기존 1.5초 지연·5초 최대 대기와 응답 직후 자동 큐 배출을 대체한다. 최신 대기 스냅샷 하나에 최초 대기 시각·마지막 변경 시각·수동 저장 우선순위를 보관한다. 자동 저장은 3초 지연, 업로드 시작 간 최소 5초, 연속 변경 최대 15초 정책을 함께 사용한다. 진행 중인 쓰기는 고정하며, 그동안 쌓인 변경도 같은 정책을 통과한다. 별도 자동 저장 타이머와 큐를 하나의 스케줄러로 통합한다.

수동 저장은 지연을 건너뛰며, 이미 업로드 중이면 최신 대기를 수동 요청으로 승격한다. 실제 저장 성공이 확인된 내용·파일명과 같고 오류 상태가 아니면 일반 저장의 원격 조회·쓰기를 생략한다. 문서 전환·연결 해제·저장 오류는 기존 취소/중지 규칙을 유지한다. 확정 편집의 250ms IndexedDB 초안 보관은 별도로 유지하며 보관을 끈 설정을 존중한다.

최신 버전 조회는 캐시하지 않고 실제 저장 직전에 수행한다. 캐시는 로컬 편집과 성공 확인된 스냅샷에 한정하며 권한 토큰을 저장소에 추가하지 않는다. 시간 정책과 버퍼 병합은 순수 로직 테스트, 실제 요청 수와 초안 선행 보관·동기화·충돌은 모킹된 Drive HTTP를 사용하는 브라우저 테스트로 검증한다.
