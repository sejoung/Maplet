# ADR 0015: 의미 기반 번역 키

- 상태: 채택
- 날짜: 2026-10-21
- 대체: 한국어 문장을 번역 키로 쓰던 방식

## 배경

화면 문구는 한국어 원문 문장 자체를 키로 쓰고 `en.json`에만 영어 번역을 두었다. 문구를 고치면 키가 바뀌어 번역이 끊기고, 코드에서 문장이 무엇을 뜻하는지 알기 어려우며, 다른 언어를 추가할 때 기준 언어가 코드에 섞여 있었다. 사용자 검토에서 내부 키를 정하고 각 언어로 번역하는 방식을 요청했다.

## 결정

- 모든 화면 문구는 `영역.이름` 형식의 고정 키(`menu.copy`, `edit.nodeNotFound`, `drive.savedDrive`)로 쓴다. 영역은 `app`·`canvas`·`common`·`drive`·`edit`·`editor`·`file`·`header`·`menu`·`meta`·`nodeTools`·`settings`·`shortcuts`·`style`·`toolbar`이며, 여러 영역에서 쓰는 문구는 `common`에 둔다.
- 언어마다 같은 키 집합의 카탈로그(`src/i18n/locales/ko.json`, `en.json`)를 둔다. 언어에 키가 없으면 한국어로 대체한다. 영어 복수형은 `{ one, other }`를 쓴다.
- `src/i18n` 밖의 코드에는 한국어 문구를 쓰지 않는다. 언어 이름(한국어·English)은 각 언어로 표시하므로 `i18n/locale.ts`의 상수로 둔다. 노드 기본 제목 같은 문서 데이터는 번역 키가 아니다.
- `AppError`와 경고는 키와 값을 가진다. 개발자용 `message`는 `file.filesMustMibSmaller (limit: 10)`처럼 키와 값을 보여 준다.
- 이전 버전이 문서·초안에 저장한 한국어 경고 문장은 한국어 카탈로그를 역으로 찾아 계속 번역한다. 더 이상 만들지 않는 문장은 `file.legacy*` 키로 남긴다.
- 카탈로그 테스트는 두 언어의 키와 `{매개변수}` 일치, `src/i18n` 밖의 한국어 문구 부재, 코드가 쓰는 키의 존재와 쓰지 않는 키의 부재를 검사한다.

언어를 추가할 때는 같은 키로 카탈로그를 만들고 `core.ts`의 카탈로그 목록과 `Language`, 언어 감지·선택 목록에 등록한다.

## 검증

단위·통합 테스트는 화면 밖의 상태와 오류를 키로 비교하고, 화면을 그리는 테스트와 브라우저 테스트는 한국어·영어 번역 결과를 그대로 확인한다. 이전 형식의 한국어 경고 문장이 영어로 번역되는지도 검사한다.
