# 선택적 Google Drive 연결

기본 앱은 자격 증명·로그인 없이 로컬 `.maplet` 편집과 `.mup` 가져오기·내보내기가 가능하다. Drive 연결은 배포 운영자가 다음 설정을 제공한 경우에만 활성화된다.

1. 같은 Google Cloud 프로젝트에서 Drive API와 Google Picker API를 활성화한다.
2. OAuth 동의 화면을 설정하고 `drive.file` 범위의 공개 정책을 확인한다. 테스트 모드라면 테스트 사용자를 등록한다.
3. 웹 애플리케이션 OAuth 클라이언트의 authorized JavaScript origin에 로컬 `http://127.0.0.1:5173`과 실제 배포 origin을 등록한다. 경로는 origin에 포함하지 않는다.
4. 브라우저 API 키에 웹사이트 referrer 제한과 Drive/Picker API 제한을 적용한다. Picker 공식 안내에 따라 `https://docs.google.com/*` referrer도 확인한다.
5. `.env.example`을 `.env.local`로 복사하고 Client ID, API key, 프로젝트 번호(App ID)를 입력한 뒤 재시작/재빌드한다. 세 값은 공개 브라우저 설정이다. client secret은 절대 포함하지 않는다.
6. 상단 Google Drive 버튼에서 먼저 `저장 위치 선택`을 누른다. Google 로그인 직후 내 드라이브 루트부터 하위 폴더를 탐색해 저장할 폴더를 선택한다. 폴더 이름을 확인한 뒤 `Drive에서 열기` 또는 `Drive에 저장`을 사용할 수 있다. 이미 연결되어 있으면 로그인 단계를 건너뛴다.

폴더 선택은 저장 위치 설정이며 파일을 만들지 않는다. 폴더는 연결된 세션 동안 문서와 별도로 유지하며, 로컬 파일이나 다른 위치의 Drive 파일을 열어도 바뀌지 않는다. 새 파일은 선택한 폴더에 저장하며, 이후 `Drive에 저장`은 같은 파일을 갱신한다. `다른 위치에 새 사본 저장`은 폴더를 다시 선택해 별도 파일을 만든다. 선택을 취소하면 파일을 읽거나 저장하지 않는다. 파일·폴더 선택 중에는 앱 대화상자를 닫아 Picker와 겹치지 않게 한다.

브라우저의 IndexedDB 초안은 계속 자동 보관한다. Drive 저장의 기본 형식은 `.maplet`이다. 저장 폴더를 선택하면 이후 확정된 편집을 1.5초 지연해 자동 저장한다. 선택한 폴더 안의 기존 `.maplet`을 열면 그 파일을 갱신한다. 다른 위치에서 연 파일은 첫 편집 후 선택한 폴더에 `.maplet` 사본을 만들고 이후 그 사본만 갱신한다. 원본의 부모 폴더를 확인할 수 없는 경우에도 사본으로 저장한다. 제목 입력은 Enter 또는 편집 종료로 확정한 내용을 저장한다.

Drive에서 연 `.mup` 파일도 첫 편집 후 선택한 폴더에 `.maplet` 사본으로 자동 저장하며 원래 파일을 보존한다. 폴더를 선택하거나 파일을 열기만 한 경우에는 파일을 만들지 않는다. `Drive에 저장`을 누르면 편집 전에도 현재 내용을 저장할 수 있다. 저장 폴더 변경은 기존 파일을 이동하지 않으며 다음 편집이나 수동 저장부터 새 폴더에 별도 파일을 만든다. 변경을 취소하면 기존 대상을 유지한다. 기존 `.maplet` 파일은 버전과 ETag를 검사해 갱신한다. 자동 저장 대기·진행·완료·중지 상태는 하단에 표시한다. 로컬 MUP 호환 파일은 파일 메뉴의 `.mup 내보내기`로 다운로드한다.

SDK는 Drive 화면을 열 때만 로드하며 기본 로컬 사용 중 맵 콘텐츠를 전송하지 않는다. OAuth 토큰은 메모리에만 유지하며 새로고침 후 재연결한다. 만료·거절·오프라인 오류는 로컬 초안을 유지한다. 충돌 시 새 사본, 로컬 다운로드, 명시적 덮어쓰기를 선택할 수 있다. ETag가 응답에 노출되지 않으면 안전한 자동 갱신을 거절한다.

자동 저장은 로그인·폴더 선택 창을 띄우거나 실패를 반복 재시도하지 않는다. 권한 만료·네트워크 오류·충돌이 나면 자동 저장을 멈추고, Drive 화면에서 사용자가 다시 저장에 성공하면 재개한다. 새로고침 후에는 Drive를 다시 연결하고 작업 파일을 열어야 한다. 파일 쓰기는 하나씩 실행하며 저장 중 편집한 내용은 다음 저장으로 이어진다. 문서를 바꾸면 이전 저장 결과가 새 문서의 저장 상태를 변경하지 않는다. Drive 저장 성공도 저장 완료 기준으로 반영하며, 실패·대기 중인 변경에는 페이지 이탈 경고와 초안 복구를 유지한다.

## 운영 검증

자동 검증은 HTTP 계약과 OAuth/Picker 모킹 범위다. 로그인 후 루트에서 폴더 선택으로 이어지는 동작, 폴더를 고르기 전 파일 열기·저장 비활성화, 선택만으로 파일을 만들지 않는 동작, 선택한 폴더의 부모 ID 전송, 기존 파일 갱신과 별도 사본 생성을 검사한다. 추가로 다른 폴더의 네이티브 파일과 MUP의 사본 생성·자동 갱신, 폴더 변경·취소·문서 간 유지, 편집 지연·저장 중 추가 편집·문서 전환·권한 만료·충돌 중지와 명시적 저장 후 재개를 검사한다. 공개 origin에서 실제 폴더 계층 탐색·로그인 허용·팝업 차단·권한 거절·토큰 만료·ETag 헤더 노출·버전 충돌은 실제 계정으로 추가 검증해야 한다. CI에는 실제 토큰을 넣지 않는다.
