## Red → Green 기록

1. MUP 왕복/편집/레이아웃 테스트를 먼저 추가하고 구현 파일 부재로 실패를 확인했다. 모델·명령·codec·레이아웃 구현 후 통과했다.
2. IndexedDB·Drive HTTP 계약 테스트를 먼저 추가하고 어댑터 import 실패를 확인했다. 어댑터 구현 후 통과했다.
3. 파일 경로 테스트 도우미의 Vite URL 변환 문제와 동일 Response를 재사용한 HTTP mock 오류를 수정했다. 운영 코드의 문제로 오인하지 않았다.
4. 브라우저 시나리오를 UI 완성 전에 작성했다. 실제 실행에서 트리 컨테이너 크기, Firefox 포커스 이동, 모바일 메뉴/오버레이, 버튼 이름·색 대비 문제를 확인하고 수정했다.
5. `1e999` ID/확장 필드 회귀 테스트가 실패함을 확인하고 비유한 숫자 입력을 거절하도록 수정했다.
6. 같은 방향 버튼을 다시 누르면 rank가 바뀌는 테스트와 다른 부모의 형제 anchor를 허용하는 테스트가 실패함을 확인하고 명령의 불변 조건을 수정했다.
7. 노드에 포커스가 있을 때 Cmd/Ctrl+Z 및 S가 가로막히는 E2E 실패를 확인하고 문서 단축키 이벤트가 전파되도록 수정했다.
8. 초기 구현에서는 네이티브 드래그로 부모를 변경했다. ADR 0005부터 Pointer Events 자유 배치로 대체하고, 부모 변경은 메뉴로 제공한다. 빈 캔버스 팬은 별도 시나리오로 유지한다.
9. 수동 좌표·연결선·파일 확장 테스트의 실패를 확인하고 도메인과 렌더러를 구현했다. 이동 중 연결선 갱신·배율 변환·Undo/Redo·초안/파일 왕복을 검증한다. 더블클릭 편집과 수동 배치 후 방향 변경의 회귀 실패를 발견해 각각 포인터 캡처와 가지 좌표 해제로 수정했다.

최초 작성 시점의 테스트 및 실패는 작업 중 실제 명령으로 확인했다. 이 기록은 Git 커밋별 red/green 이력을 의미하지 않는다.

## 검증 명령

```sh
npm run verify
npm run test:e2e
npm audit
node scripts/capture-ui.mjs
```

단위/통합/아키텍처 83개. 브라우저 시나리오 21종 × Chromium/Firefox/WebKit/모바일 WebKit 4환경. 접근성 axe 검사에는 텍스트 색 대비·컨트롤 이름·영역·제목을 포함한다. Playwright의 WebKit 검증은 실제 Safari 앱 전체/실기기 검증과 동일하지 않다.

도메인·유스케이스·어댑터·레이아웃 커버리지: 문장 95.52%, 분기 90.54%, 함수 95.38%, 줄 97.35%. UI와 조립 계층은 E2E로 검증하고 위 단위 커버리지 수치에는 포함하지 않는다. Google SDK 브리지는 mock 테스트에 포함한다. 실제 브라우저 화면 캡처에서 실행 오류가 없음을 확인했다.

## 외부 조건과 남은 검증

- 사용자 실제 .mup 파일은 제공되지 않았다. 5개의 합성 fixture를 사용하며 사용자 실파일 3~5개 검증은 대기 중이다.
- Google Cloud 프로젝트 자격 설정과 실제 계정은 제공되지 않았다. OAuth/Picker SDK mock과 Drive HTTP 계약은 검증했으나 실제 연결은 배포 origin에서 검증해야 한다.
- GitHub Pages workflow를 준비했으며 외부 공개 배포는 실행하지 않았다. 저장소 Pages 설정 후 workflow를 실행해야 한다.
- 첨부 이미지·HTML 콘텐츠·교차 연결은 원본 보존 대상으로, 전용 렌더링은 지원하지 않는다. 호환성 매트릭스와 ADR 0002를 참고한다.
- MapJS 실행 PoC 대신 공식 포맷·소스·의존성 조사를 근거로 독립 렌더러를 선택했다. 사용자 실파일 검증 결과에 따라 ADR을 갱신한다.

## UI 단순화 회귀 검증 (ADR 0004)

기존 화면에서 중심 노드 1개/직접 편집 수용 테스트가 실패함을 확인한 뒤 구현했다. 첫 화면의 좌우 패널·자동 색상·장식 문구를 제거하고 툴바에서 요청한 도구만 열도록 변경했다. 제목 직접 편집·Esc 취소·한글 조합 중 Enter·편집 중 Cmd/Ctrl+S·색상 선택/초기화·검색으로 접힌 노드 선택·Tab 연속 편집을 추가로 검증한다. Tab 연속 편집 시 이전 제목이 덮이는 실패를 확인하고 수정했다. 모든 기능 테스트는 새 UI 조작 경로로 갱신했다.

## 실행별 결과 검증 (ADR 0006)

통합 테스트 6개를 추가해 동일 시각 실행의 폴더 분리, 실행 완료 전 링크 미생성, 실패 결과와 종류별 최신 링크, 이전 산출물 보존, stdout/stderr 수집, 결과 경로 전달, 실패 종료 코드·시작 오류·프로세스 종료 신호를 검증한다. 최초 테스트에서 실행 도우미 모듈 부재로 실패함을 확인하고 구현했다. 실제 `npm run verify`의 커버리지·JSON·JUnit·로그를 실행 폴더에 저장하고 상대 심볼릭 링크로 접근하는 것을 확인했다. 사용법은 [개발 가이드](contributing.md#테스트-결과)에 정리한다.

## 파일 크기 제한 검증 (ADR 0007)

통합 테스트 4개로 실제 ESLint 설정의 운영·테스트·스크립트 경로에 대한 400/401줄 경계와 빈 줄·주석 포함 정책, 중첩 CSS 경로와 CRLF 개행을 검증한다. 규칙 적용 전 실패를 확인했고, 적용 후 App·Canvas·Editor의 린트 실패를 책임 분리로 해결했다. CSS도 역할별 파일로 나누어 같은 상한을 적용한다.

## 하위 가지 동반 이동 검증 (ADR 0008)

부모 드래그 시 자식 이동량이 0인 브라우저 실패와 이동 함수 부재의 단위 테스트 실패를 확인한 후 구현했다. 단위 테스트 4개로 여러 단계 가지의 상대 배치·다른 가지 유지·음수 좌표·반복 미리보기 불변성·다중 루트·접힌 하위 노드 좌표·파일 왕복·단일 Undo/Redo를 검사한다. 기존 이동 E2E에 자식·손자의 실시간 이동과 취소·다시 실행·루트 이동을 추가하고, 접힌 가지를 옮긴 후 초안 복구하는 시나리오를 추가한다.
